# CADVEX AI Engine Overview

The `backend` is a FastAPI-powered Python microservice responsible for blueprint image audits, text-to-CAD synthesis, and spatial code editing using the Google Gemini API.

---

## 1. Service Boundaries & API Map

The FastAPI service runs on `http://127.0.0.1:8000`. It is stateless and exposes three endpoints:

| Endpoint | Method | Input Type | Output Type |
|---|---|---|---|
| `/health` | `GET` | None | JSON status code validation |
| `/api/v1/generate` | `POST` | `multipart/form-data` (Prompt, Model, drawing File) | JSON `GenerateResponse` (Script + variables dictionary) |
| `/api/v1/edit` | `POST` | `application/json` (`EditRequest` containing current code & target coordinates) | JSON `GenerateResponse` (Modified script + variables dictionary) |

---

## 2. API Data Contracts

### 2.1 `EditRequest` (Pydantic Schema)
Defines the parameters required to perform a surgical script refinement:
* `prompt` (string): Sizing or functional modification request.
* `current_code` (string): The active OpenSCAD code.
* `target_point` (optional list of 3 floats): Click coordinates used to specify the origin of the modification.
* `model` (string, defaults to `"gemini-3.1-flash-lite"`): Active LLM engine.

### 2.2 `GenerateResponse` (Pydantic Schema)
Defines the payload returned by both endpoints:
* `openscad_script` (string): The generated or modified script.
* `parameters` (dict): The extracted top-level variables.

## 3. Core Services

### 3.1 LLMCodegenService (`app/services/llm_codegen.py`)
Encapsulates Google GenAI SDK calls. It maintains three main pipelines:

#### `upload_file_to_gemini(file_bytes, mime_type, filename)`
* Writes uploaded drawing bytes to a temporary file on the host.
* Uploads the file via the Gemini Files API (`client.files.upload`).
* Polls until the file status transitions from `PROCESSING` to `ACTIVE`.

#### `audit_blueprint(image_bytes, mime_type, filename)`
* Checks the in-memory cache using the file's MD5 hash. If a cached feature map is found, returns it immediately.
* If a cache miss occurs:
  1. Uploads the blueprint drawing file (JPEG/PNG/PDF) to Gemini Files API.
  2. Submits the file reference to Gemini Vision.
* Extracts a structured JSON feature-map defining envelopes, datum lines, pocket depths, hole PCD patterns, and surface finishes.
* Caches the output feature-map and file object.

#### `generate_script(prompt, image_bytes, mime_type, feature_map, base_code, selection_context, filename)`
* Reuses the cached Gemini file reference if available.
* Takes the feature-map and user prompts.
* Prompts Gemini to write a parameterized OpenSCAD script, formatting variables under `// PARAMETERS_START/END` comments.

#### `edit_script(prompt, current_code, target_point)`
* Modifies an existing script in place.
* Automatically formats and appends coordinate information:
  `[System Context: The user clicked on the 3D mesh at absolute coordinates X: {x}, Y: {y}, Z: {z}. Use this exact spatial location as the origin/target for the requested modification.]`
* Runs the prompt against `EDIT_SYSTEM_PROMPT` to enforce modular code modifications.

## 4. Script Sanitizer & Security Guards (`router.py`)

Every script generated by the LLM is automatically processed through `_sanitize_script` before leaving the backend:

1. **BOSL2 Include Strip**: Hallucinated libraries like `include <BOSL2/std.scad>` are stripped out to guarantee the code remains compatible with vanilla OpenSCAD environments.
2. **Resolution Cap ($fn)**: To prevent WebAssembly thread lockups in the browser, any resolution setting (`$fn = N`) exceeding `32` is capped to `32`.
3. **Resolution Inject**: If `$fn` is not declared, the backend prepends `"$fn = 32;"` to the top of the file.
4. **Epsilon Inject**: If `difference()` blocks are used but no `eps` variable is found, the backend injects `eps = 0.02;` before the operations, ensuring stable co-planar boolean calculations.
